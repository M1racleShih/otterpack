# 版本与补丁

我希望这里分享的东西尽量接近自己正在用的样子。不过，有些改动还没有在各自项目里正式发布，所以这次记录了公开提交，也把需要的改动整理成补丁。具体版本以 `catalog.json` 为准，独立项目仍在原仓库维护。

## 三组补丁

| 组件 | 选入的改动 | 未选入的本地内容 |
| --- | --- | --- |
| pi-hud | 当前运行源码，含速度统计、NewAPI 与 Kimi 额度适配；相关测试与边界检查 | 私人额度 profiles、认证文件、性能探测脚本、开发技能与本机规划资料 |
| conv-docs | 安全阅读样式隔离、伴生 CSS、相关测试和公开使用说明 | 本机服务状态、发布目录清单、访问 token、技能池锁定信息 |
| herdr-remote-solution | Cookie 认证改进、transcript 兼容、羊皮纸终端色与资源缓存修复；相关测试 | 未公开的 SilverBullet 集成计划和部署材料、远程地址与会话资料 |

Herdr Remote 的本地 HEAD 含尚未推送的提交，因此本包从**已公开的 b01755f** 重建，把所需运行代码变化纳入同一补丁。HUD 的上游 package.json 版本号仍是 0.2.1，不能据此把本地快照当作一个新的正式版本。本包采用日期与 SHA-256 标识快照。

青鸟仅引用公开提交，未把其本地尚未发布的改动加入本包。

## 还原方式

需要 Git、Python 3.11+ 和访问 GitHub 的网络。在 Otterpack 根目录执行，目标目录必须尚不存在，父目录必须存在：

```sh
python3 scripts/materialize.py pi-hud ../otterpack-pi-hud
python3 scripts/materialize.py conv-docs ../otterpack-conv-docs
python3 scripts/materialize.py herdr-remote-solution ../otterpack-herdr-remote
```

脚本只下载固定提交、检查并应用补丁，逐项核对改动文件的 SHA-256，再把结果放到新目录。它不会安装依赖、执行组件代码、启动服务或写入个人配置。还原目录保留原来的 Git 提交，补丁体现为未提交改动，方便查看具体改了什么。

同样可以用目录中的其他组件 ID 下载固定源码。核对代码与对应 README 后，再决定自己的安装步骤。如果上游删除了某个提交，下载可能失败；这时要先审查准备替换的版本，不能直接切到最新版。

## 后续怎么更新

当原项目吸收改动并发布新版本时，把目录更新到新的公开提交，删除已不再需要的补丁，重新验证相关功能和截图。不要覆盖使用者手动改过的配置，也不要在更新一个工具时顺便升级整套工作环境。
