# 我怎样把它们串起来

## 开工：先把问题说清楚

写下目标、限制和完成后可观察的结果。给 agent 足够的上下文，也留出它指出矛盾和缺失信息的空间。用 dynamic-skills 选择当前项目需要的技能，减少无关的说明。

## 工作中：让注意力有地方落下

在 Herdr 中按项目组织终端，用 Radar 找到正在等回复的任务。Pi 的输入框保持简洁，HUD 留住模型、上下文和活动信息。羊皮纸主题让不同工具的成功、警告、错误颜色尽量一致。

并行工作时，明确文件归属和交接条件。cd-connect 适合有清晰范围、可以独立检查结果的任务。它保留执行端的原生权限与审批；任务是否完成，要看文件与证据。

## 中途离开：把成果做成可读文档

让报告能脱离聊天独立成立：先写结论，再写理由、来源和未解决的问题。通过 conv-docs 预览明确选中的文档，在手机上继续阅读。复杂决策值得换一个节奏看一遍。

## 收工：检查这一次真正发生了什么

检查改动是否解决最初的问题，测试是否覆盖改变的行为，是否保留了别人已有的工作。区分源码检查、离线运行、真实上游调用与人眼确认，报告实际做过的验证。

留下版本、配置取舍和恢复方式。下一次更新有据可查，下一位使用者也能知道哪些结论适用于自己的环境。

这些做法来自我的日常取舍。你可以替换工具、删减步骤，让这只小獭的工具袋适合自己的手。
