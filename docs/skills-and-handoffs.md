# 我怎么管理 skill，怎么交接任务

## dynamic-skills

[dynamic-skills](https://github.com/M1racleShih/dynamic-skills) 管理共用技能库，并让每个项目选择自己的工作集与固定版本。

我希望 skill 能根据项目和任务来选。所以会先看看当前要做什么，再从技能池里挑合适的，读完说明后决定是否启用。换到另一个项目，就保留它自己的选择；更新技能池时，也不要顺手把所有项目的固定版本都改了。

安装与命令以目录中固定提交的 README 为准。本包不复制整套个人技能池。第三方技能可能包含脚本、外部服务要求和自己的许可，导入时逐项阅读。

## cd-connect

[cd-connect](https://github.com/M1racleShih/cd-connect) 可以把任务交给本机 DSH Desktop 执行，再取回执行记录和结果来检查。这里收录的是 0.5.0，对应 DSH 0.2.1-rc.2 desktop profile；使用前先看安装说明，确认 bridge health 正常。

交任务时，可以按这个格式把要求写清楚：

```text
目标：完成什么，用户最终会观察到什么。
工作目录：明确的绝对路径。
允许范围：可以修改哪些文件，允许哪些外部操作。
排除范围：哪些已有工作与服务必须保留。
约束：沿用原生模型、权限和审批；不要扩大任务。
验收：可运行的检查、预期结果，以及需要报告的限制。
```

执行完了之后，再检查实际文件和这次的执行记录。哪里通过了，哪里还需要调整，要具体说明。需要人工批准的操作，回到 DSH 自己的界面处理；如果不确定任务到底执行到了哪一步，先查原任务，不要直接重发一遍。

这里也记录一下实际情况：制作 Otterpack 时检查了本机桥接，但当时连接不上，所以没有派发 DSH 任务。cd-connect 仍然收录在这里，不过工具测试和真实桌面连接要分开看，不能拿以前连通过来说明这次也通过了。
