# 技能跟项目走，任务带着边界走

## dynamic-skills

[dynamic-skills](https://github.com/M1racleShih/dynamic-skills) 管理共用技能库，并让每个项目选择自己的工作集与固定版本。

我的选择顺序是：先确定当前交付物，再找能帮助完成它的技能，阅读说明后决定是否启用。换一个项目时，保留它自己的选择；更新技能池时，也不顺手改变所有项目的锁定版本。

安装与命令以目录中固定提交的 README 为准。本包不复制整套个人技能池。第三方技能可能包含脚本、外部服务要求和自己的许可，导入时逐项阅读。

## cd-connect

[cd-connect](https://github.com/M1racleShih/cd-connect) 把任务交给本机 DSH Desktop 执行，再把当前运行的证据带回审查。目录固定的是 0.5.0，对应 DSH 0.2.1-rc.2 desktop profile；先阅读它的安装说明并确认 bridge health。

一个可复用的交接模板：

```text
目标：完成什么，用户最终会观察到什么。
工作目录：明确的绝对路径。
允许范围：可以修改哪些文件，允许哪些外部操作。
排除范围：哪些已有工作与服务必须保留。
约束：沿用原生模型、权限和审批；不要扩大任务。
验收：可运行的检查、预期结果，以及需要报告的限制。
```

执行完成后，我检查实际文件和当前运行证据，再记录通过或具体返工意见。需要人工批准时回到 DSH 的原生界面处理。出现不确定的执行结果时，先核对原任务，避免重复执行同一个动作。

本次 Otterpack 制作检查了本机桥接健康，桥接不可达，因此没有派发 DSH 任务，也没有把历史可用性记作本次通过。cd-connect 仍作为已选工具收录，其测试与桌面连接是不同层面的验证。
